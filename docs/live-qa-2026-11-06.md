Follow-up changes address the remaining observations:

- Mint drafts now run the same recipient readiness component as transfers, before compilation. Draft edits explain why the old plan and approval were cleared.
- Native receipt inspection/recovery tracks each read separately. Another receipt remains available, and success, failure or timeout releases the affected button. A transient recheck failure preserves an existing verified receipt rather than replacing its proof with an uncertain state. Journal writes still acquire the wallet-operation lock.
- Native quote errors appear beside the quote controls. Excessive fee precision has its own explanation. Tiny reverse amounts that the chain cannot quote show an actionable error rather than an off-screen message.
- Runtime, balance, fee, approval, quote and receipt reads show explicit progress with elapsed time. Quote/verification and approval reads have bounded waits; they never retry a signed broadcast. Progress feedback is not a claim that RPC latency has been eliminated.
- The transaction review refreshes its displayed fee from the same live preflight used for policy approval. Metadata rebinding still discards the old approval and fee estimate; a new approval check is required and supplies a fresh estimate. Genuine metadata changes are not suppressed for the recording.
- The optional team connection form asks for a backend URL without presenting a fictitious Railway hostname.

Focused regression tests cover both mint-draft readiness and amount/recipient invalidation, pending-read feedback, two independent receipt verifications, failure recovery, fee precision, tiny reverse quote errors and late/timed-out reads.
