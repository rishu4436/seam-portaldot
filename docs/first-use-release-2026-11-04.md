# First-transaction improvements — 4 November 2026

Held Assets balances now load after wallet/network selection without entering an ID. Discovery enumerates Assets.Asset keys using metadata, reads balances at a finalized block and includes only positive holdings or explicitly requested IDs. Pages are capped at 32 keys, reads have concurrency four, and each user read scans at most four pages (128 registered assets). Larger networks offer Find more assets. Pagination keeps the original block, merges by asset ID and discards results after account/network changes. Invalid/repeated/foreign-prefix keys and RPC failures produce incomplete status; incomplete discovery is never labeled an empty wallet. Manual lookup remains available.

Recipient readiness reads account providers, asset self-sufficiency and minimum balances. It distinguishes ready account requirements, missing native funding, known minimum-balance failures and unknown reads. Readiness is an observation, not execution proof. The first assets.transfer step is checked again during preflight before signing. Later steps may depend on earlier effects; the existing policy and signed dry runs remain authoritative. This check does not guarantee asset permissions, unfrozen status or successful execution.

The review panel projects decoded compiled calls: full sender/recipient addresses, asset ID, exact base-unit amount, expected effect, native value where relevant, actual preflight fee estimate and separate policy fee cap. Missing estimates stay unavailable, and runtime rebinding clears the old displayed estimate. Token decimals are used for native fees only; asset amounts keep their explicit base units.
